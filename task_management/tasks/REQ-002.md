# REQ-002

## Заголовок
**Read-only диагностический снимок состояния gRPC-соединения клиента (`ConnHealth`)**

## Jira ID
**Jira**: _(нет; потребитель — funding-bot BFF, задача FB-392 health-эндпоинт)_

---

## WHY

Потребитель библиотеки — **BFF funding-bot** — реализует health-эндпоинт `GET /api/v1/health`, который по каждой gRPC-зависимости собирает диагностику в формате `{ state, target }`:
- `state` — текущее `connectivity.State` соединения (`ClientConn.GetState()`),
- `target` — dial-адрес (`ClientConn.Target()`),

и маппит это в «светофор» (ok/degraded/down).

Сейчас `auth-client-go` держит `grpcConn *grpc.ClientConn` приватным и **не предоставляет никаких аксессоров** (нет `GetState()`, `Target()`, `Conn()`). Поэтому потребитель вынужден отдавать по `auth` **синтетический** статус (только факт инициализации клиента) и `target = "n/a"`. Это снижает диагностическую ценность health-эндпоинта (не видно реального состояния и адреса auth-соединения).

Нужно дать потребителю **реальные** данные о соединении, **не раскрывая сам `*grpc.ClientConn`** — иначе внешний код сможет его закрыть/сломать, нарушив инкапсуляцию и жизненный цикл клиента.

---

## WHAT

Добавить публичный метод на `*Client`, возвращающий **read-only value-снимок** состояния его gRPC-соединения в том же формате, что собирают потребители.

### Предлагаемый API

```go
// ConnHealth is a read-only snapshot of the client's underlying gRPC
// connection. It is a by-value copy: it does NOT expose *grpc.ClientConn,
// so external code cannot mutate or close the connection.
type ConnHealth struct {
    // State is the current gRPC connectivity state of the connection.
    State  connectivity.State
    // Target is the dial-target (host:port) the client connects to.
    Target string
}

// ConnHealth returns a snapshot of the client's gRPC connection state and
// target. O(1), no network call. Safe for concurrent use.
func (c *Client) ConnHealth() ConnHealth
```

### Функциональные требования

1. Метод `ConnHealth() ConnHealth` на `*Client`.
2. Возвращает реальное `connectivity.State` (`c.grpcConn.GetState()`) и `Target` (`c.grpcConn.Target()`).
3. **Без сетевых вызовов** (O(1)); потокобезопасно (методы `ClientConn` goroutine-safe).
4. nil-guard: если `c.grpcConn == nil` → `ConnHealth{State: connectivity.Shutdown, Target: ""}`.
5. **Не** экспонирует `*grpc.ClientConn` (ни как поле, ни как возвращаемое значение, ни через геттер).

### Нефункциональные требования

- Аддитивное, **несломающее** изменение публичного API → minor-бамп версии **v0.3.0** (pre-1.0).
- Запись в `CHANGELOG.md` и раздел в `README.md` с примером интеграции.
- Юнит-тесты (включая nil-guard).
- `make audit` (vet + lint + test) и `make test-race` — зелёные.

### Ограничения и допущения

- Возвращается состояние **соединения** (connection-level), а не результат активного health-RPC к auth-серверу. Активный probe (`Ping(ctx)`) — вне scope, может быть добавлен позже отдельным методом без слома.
- Тип `connectivity.State` намеренно используется как возвращаемое значение (это value-enum из `google.golang.org/grpc/connectivity`, а не сам conn) — потребитель (BFF) уже маппит из него; так формат снимка совпадает с тем, что BFF собирает по остальным сервисам.
- Структуру `ConnHealth` проектировать расширяемой: будущее добавление полей (например `LastError`, `LatencyMs`) должно быть аддитивным.

### В рамках реквеста

### Вне рамок реквеста

- Активный health-probe RPC (`Ping`/`HealthCheck`) к auth-серверу.
- Изменение существующих методов (`Login/Refresh/Logout/...`).
- Любое раскрытие `*grpc.ClientConn`.

**В3**: Активный health-RPC или состояние коннекта?
**О3**: Только состояние коннекта (`GetState()`/`Target()`), без сети, O(1). Активный probe — отдельная будущая задача, вне scope.

**В4**: nil `grpcConn`?
**О4**: Вернуть `{State: connectivity.Shutdown, Target: ""}`.

**В5**: Версия и релиз?
**О5**: v0.3.0 (аддитивно, pre-1.0). Поскольку `make release` интерактивный — тег поставить явно: обновить CHANGELOG, влить в `main`, `git tag v0.3.0 && git push origin main --tags`.

**В6**: Имя метода/типа?
